# Quick-Cluster

One click (okay, three) to spin up a **3-node K3s demo cluster on AWS** using Spacelift.  
Behind the scenes it wires together OpenTofu → Ansible → Kubernetes stacks, uploads the kubeconfig to S3 and prints a ready-to-copy command.

---

## 🚀 5-Minute Quick Start (GUI-only)

1. **Create the Blueprint**  
   In Spacelift, go to **Blueprints → Create blueprint**.  
   Copy-paste the YAML from [`blueprints/tofusible-admin.yaml`](./blueprints/tofusible-admin.yaml) (repo root) into the editor **or** use the file picker to load it, then click *Publish*.

2. **Launch your demo**  
   Click **Create from blueprint**, pick an AWS region / instance size and hit *Create Stack*.

3. **Download kubeconfig & explore**  
   When the run completes (~10 min) copy the one-liner printed at the bottom of the logs:

   ```bash
   aws s3 cp s3://<bucket>/kubeconfig-latest.yaml ~/.kube/config
   kubectl get nodes
   ```

That’s it — zero local tooling required.

## 🗂️  Repo Layout (for the curious)

```
blueprints/              # Spacelift blueprint
modules/tofusible_host/  # OpenTofu helper module (inventory data)
stacks/
  admin/                 # Orchestrates the entire demo
  tofu/                  # OpenTofu stack – EC2 instances
  ansible/               # Ansible stack – installs K3s
  kubernetes/            # Kubernetes stack – deploys manifests
```

Each directory has its own README if you want a deep dive.

## 🤔  How does it work internally?

1. **Admin stack** (generated by the Blueprint) creates:  
   • an S3 bucket,  
   • an SSH-key context,  
   • child stacks for OpenTofu, Ansible and Kubernetes.
2. **OpenTofu stack** spins up 3 EC2 instances and outputs an inventory.  
3. **Ansible stack** installs K3s, saves `kubeconfig` to S3.  
4. **Kubernetes stack** downloads that kubeconfig and applies the demo manifests.

The four stacks share a random run-tag so they stay isolated from each other, which means any number of users can launch parallel demos without clashing.
