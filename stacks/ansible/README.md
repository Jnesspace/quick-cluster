# Ansible K3s Deployment Stack

This stack deploys a complete K3s Kubernetes cluster on the virtual machines created in the OpenTofu stack.

## What It Does

- **Installs K3s server** on the first node (tofu-dev-1)
- **Installs K3s agents** on the remaining nodes (tofu-dev-2, tofu-dev-3)
- **Configures cluster networking** with proper security groups
- **Outputs kubeconfig** for immediate cluster access
- **Verifies cluster health** and displays running pods

## K3s Cluster Architecture

- **Server Node**: `tofu-dev-1` - Runs the K3s server with the Kubernetes API
- **Agent Nodes**: `tofu-dev-2`, `tofu-dev-3` - Join as worker nodes
- **Networking**: Flannel CNI with VXLAN backend
- **Version**: K3s v1.28.5+k3s1

## Security Configuration

The deployment automatically opens the following ports:
- **22** - SSH access
- **6443** - Kubernetes API server (external access)
- **8472/udp** - Flannel VXLAN (cluster internal)
- **10250** - Kubelet metrics (cluster internal)
- **30000-32767** - NodePort services (external access)

## Accessing Your Cluster

After deployment, the playbook outputs the complete kubeconfig. Look for the section in the Ansible logs:

```
🔐 KUBECONFIG (save this to ~/.kube/config):
```

Copy the kubeconfig content and save it locally:

```bash
# Save the kubeconfig
echo "KUBECONFIG_CONTENT" > ~/.kube/config

# Test cluster access
kubectl get nodes
kubectl get pods -A
```

## Files Explained

- `playbook.yml` - Main Ansible playbook that deploys the K3s cluster
- `tofusible.yml` - Dynamic inventory configuration
- `inventory_plugins/tofusible.py` - Dynamic inventory plugin that reads from OpenTofu output

## Customization

You can modify the K3s deployment by editing variables in `playbook.yml`:
- `k3s_version` - Change the K3s version
- `k3s_token` - Modify the cluster join token (auto-generated by default)
- Add additional K3s flags as needed
